## 1. Skeleton

- `project.yml` (XcodeGen 2.46) generates `Apps/FlyCam.xcodeproj` (git-ignored in `Apps/.gitignore`, regenerated by every script).
- Targets: `DirectorCore` (macOS framework), `DirectorCoreTests` (unit tests), `DirectorApp` (macOS app),
  `director-cli` (macOS tool), `CaptureApp` (iOS app). Code in `Apps/Shared` is compiled into both
  DirectorCore and CaptureApp, so phone-side logic is tested on the Mac.
- Packages: `Packages/FlyCamKit` from track-l (local path), MetalSplatter 1.0.1 (vendored, see below).
- Scripts: `scripts/build_mac.sh`, `scripts/build_ios.sh` (generic/platform=iOS, `CODE_SIGNING_ALLOWED=NO`),
  `scripts/test_mac.sh`, `scripts/generate.sh`. Build output goes to `Apps/.build/`.

### Metal Toolchain missing (decision)

Xcode 27.2 on this Mac has no Metal Toolchain component, so no `.metal` file can be compiled at build time,
and installing it is not allowed for this track. Therefore:

- MetalSplatter 1.0.1 is vendored in `Apps/Vendor/MetalSplatter` with one patch: if there is no precompiled
  library, it compiles its unchanged shader sources at runtime (`Apps/Vendor/MetalSplatter/VENDORED.md`).
- DirectorCore's own shaders are Swift string constants compiled at runtime with `makeLibrary(source:)`.

With the toolchain installed, project.yml can point back at the upstream URL with `exactVersion: 1.0.1`.

## 2. Renderer (Phases 0 and 4)

`Apps/DirectorCore/Rendering/`, all offscreen (no window, no drawable):

- `SplatScene`: loads `.ply` (3DGS layout; also `.splat`/`.spz`) with MetalSplatter's SplatIO, renders with
  `SplatRenderer` into `SplatRenderTargets` (colour rgba16Float linear premultiplied, depth32Float NDC depth).
  Camera = FlyCamKit `PinholeCamera`: view = `c2w.rigidInverse`, projection = `PinholeCamera.projectionMatrix`
  built from fx, fy, cx, cy (off-centre frustum, plan.md section 5).
- Depth: MetalSplatter's high-quality depth path stores the alpha-weighted NDC depth; DirectorCore's compute pass
  `linearizeDepth` converts it to metric depth along the viewing axis in an r32Float texture (0 = no content),
  readable by any later pass and exportable as `.f32` (`Readback.writeF32`, docs/protocol.md 2.5a). No fork needed.
- `renderSettled`: waits for a MetalSplatter depth sort made for exactly this camera (deterministic offline frames).
- `Compositor`: video frame pass (BGRA pixel buffer via `CVMetalTextureCache`, sampled as sRGB, resampled into a
  linear layer) and mix pass (`wA * videoA + wR * (splat over background) + wB * videoB`) into a bgra8 sRGB target.
- `GaussianPLY`: writer for 3DGS PLY files (generated fixtures).

Tests (`Apps/DirectorCoreTests/RendererTests.swift`, `CompositorTests.swift`), 1280x720, fx 1100, fy 1000,
cx 703.25, cy 301.75 (principal point 64 px / 58 px off centre), 20 Gaussians from 1.2 m to 9 m incl. near corners,
written to PLY and loaded through MetalSplatter:

| Test | Threshold | Measured |
|---|---|---|
| (a) alpha centroid vs. plan.md section 5 projection | < 1 px | worst 0.007 px |
| (b) metric depth read back at the projected pixel | < 2 % | worst 0.002 % |
| video + mix pass at wA = 1 / wB = 1 reproduces the frame | <= 1 LSB | passes |
| 50/50 mix equals the linear-light average | < 1.01 LSB | passes |

Request for track-l (not blocking): FlyCamKit `BlendWeights` has no public initialiser; DirectorCore uses its
own `MixWeights` (initialisable from `BlendWeights`).

## 3. RecordedSource

`Apps/DirectorCore/Sources/`:

- `FrameSource` protocol (plan.md section 4): `frame(nearest:)` returns a `SourceFrame` (index, time, phone time,
  `PinholeCamera`, tracking, 32BGRA pixel buffer). Nearest-frame rule with ties to the earlier frame
  (docs/protocol.md 4).
- `RecordedSource`: reads `meta.json`, `frames.jsonl` (FlyCamKit `SessionIO`, validated with `SessionValidation`)
  and `pose_override.json`; decodes `video.mov` with `VideoFileReader` (AVAssetReader, BGRA, sequential with seeks
  by sample presentation time; video frame i = line i). Time bases: Mac clock (`t + clock_offset`, default when
  meta.json has an offset), phone clock, or seconds since the first frame. Rejects a video/metadata frame count mismatch.
- `Apps/Shared/Capture/SessionVideoWriter.swift`: HEVC `video.mov` writer (no frame reordering, keyframe every 1 s),
  shared by the CaptureApp recorder and the fixture generator.
- Fixtures (`Apps/DirectorCore/Fixtures/`): `SyntheticRoom` (about 60k flat Gaussians: checkerboard floor, striped walls,
  two boxes), `SyntheticSession` (renders tripod clips from the splat, HEVC, with the frame index stamped as 16
  black/white squares by `FrameCode`, plus meta.json/frames.jsonl), two-camera fixture with different phone clocks
  on one Mac clock.

Tests (`RecordedSourceTests`): every one of 60 frames served by timestamp (with +-0.4 frame jitter) decodes to the
right frame (stamped index read back from the HEVC frame); backward and random access; clamping; tie rule; two
sessions aligned on the Mac clock; pose override and the other time bases; frame count mismatch rejected.

## 4. Transition (Phase 4)

`Apps/DirectorCore/Transition/`:

- `TransitionController`: preview/program workflow (select preview, take; preview locked in flight; on landing B
  becomes program and A preview). Path = FlyCamKit `TransitionPath` (interest point with fallbacks, orbit, slerp,
  log-space focal length, floor guard, smootherstep, 15 % fades), rebuilt every frame from the latest poses. Landing
  timestamps within 1 us of T are snapped.
- `ProgramRenderer`: video state = video pass + mix (untouched video); flight = splat from the virtual camera
  (`renderSettled` offline, latest sort live) + video passes + mix with the FlyCamKit blend weights.
- `OfflineTransition` + `director-cli render-transition <sessionA> <sessionB> <splat.ply> --out <file.mp4>`:
  timeline pre (0.5 s) + T (1.2 s) + post (0.5 s) on the Mac clock when both sessions have a clock offset, else
  from each session's first frame; HEVC MP4 plus `<file.mp4>.json` per-frame log (u, s, weights, source frames,
  virtual camera, interest point). No window, runs from a shell.
- `TransitionVerification` + `director-cli verify-transition`: scope test (c) checks, also used by the XCTest.
- Other CLI commands: `make-fixture`, `render-frame` (PNG + `.f32` depth for the Phase 3 refine_pose export), `inspect`.

Colour finding: untagged BGRA buffers let VideoToolbox guess the colour space (SMPTE-C primaries, BT.601 matrix at
640x360), which cost about 10 dB PSNR per re-encode (34.5 dB instead of 45 dB in an isolated test). All buffers
DirectorCore creates and all files SessionVideoWriter writes are now tagged Rec. 709.

Test (c) (`TransitionTests`, also run through the CLI by `scripts/test_mac.sh`), generated two-camera fixture
(640x360, 60 frames at 30 fps, different phone clocks on one Mac clock):

| Check | Threshold | Measured |
|---|---|---|
| first output frame vs. source A frame | > 35 dB | 72.0 dB |
| take frame (s = 0) vs. source A frame | > 35 dB | 72.4 dB |
| landing frame (s = 1) vs. source B frame | > 35 dB | 63.4 dB |
| last output frame vs. source B frame | > 35 dB | 63.3 dB |
| middle frame (s = 0.5): pixels differing from the empty background | > 50 % | 100 % |
| middle frame vs. direct splat render from the logged virtual camera | > 30 dB | 45.9 dB |
| middle frame vs. video A / video B | at least 3 dB below the render | 10.7 / 10.9 dB |

Also: virtual camera at the take equals camera A exactly; weights are video A only before the take, video B only
after landing; controller and floor-guard unit tests.
